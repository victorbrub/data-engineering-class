# Requirements Detector

Automatically detect and generate `requirements.txt` files by analyzing Python import statements in your project.

## Features

- 🔍 **Automatic Detection**: Scans all Python files in a directory
- 📦 **Smart Mapping**: Maps import names to correct PyPI package names (e.g., `cv2` → `opencv-python`)
- 🚫 **Standard Library Filter**: Ignores built-in Python modules
- 📌 **Version Pinning**: Optionally includes installed package versions
- 🎯 **Configurable**: Excludes common directories like `venv`, `__pycache__`, etc.

## Usage

### Basic Usage

Scan the current directory:
```bash
python detect_requirements.py
```

### Scan Specific Directory

```bash
python detect_requirements.py /path/to/your/project
```

### Custom Output File

```bash
python detect_requirements.py -o custom_requirements.txt
```

### Without Version Pinning

Generate requirements without specific versions:
```bash
python detect_requirements.py --no-versions
```

## How It Works

1. **Scans** all `.py` files in the specified directory (excluding virtual environments, cache, etc.)
2. **Parses** Python AST to extract `import` and `from ... import` statements
3. **Filters** out standard library modules
4. **Maps** import names to PyPI package names
5. **Detects** installed versions (if requested)
6. **Generates** a clean `requirements.txt` file

## Package Name Mapping

The script includes mappings for common packages where the import name differs from the PyPI name:

| Import Name | PyPI Package |
|-------------|--------------|
| `yaml` | `PyYAML` |
| `cv2` | `opencv-python` |
| `sklearn` | `scikit-learn` |
| `PIL` | `Pillow` |
| `bs4` | `beautifulsoup4` |
| `dotenv` | `python-dotenv` |
| `dateutil` | `python-dateutil` |
| `psycopg2` | `psycopg2-binary` |
| `azure.eventhub` | `azure-eventhub` |
| `azure.identity` | `azure-identity` |
| And more... |

## Excluded Directories

By default, the following directories are excluded from scanning:
- `venv`, `.venv`, `env`, `.env`
- `__pycache__`
- `.git`
- `node_modules`
- `dist`, `build`
- `.ipynb_checkpoints`
- `logs`, `files`
- `test`, `tests`, `solutions`

## Output Format

Generated `requirements.txt` includes:
- Header comment indicating auto-generation
- Sorted list of packages
- Version pinning (if enabled)

Example output:
```txt
# Auto-generated requirements file
# Generated by detect_requirements.py

pandas==2.1.0
psycopg2-binary==2.9.9
PyYAML==6.0.1
requests==2.31.0
```

## Tips

1. **Before installing**: Run this script to verify all required packages are detected
2. **After development**: Update your requirements.txt automatically
3. **Version control**: Commit the generated file to ensure reproducible environments
4. **Review the output**: Always check the generated file to ensure correctness

## Integration with Projects

You can integrate this into your setup scripts:

```bash
# In your setup.sh
echo "Detecting requirements..."
python detect_requirements.py

echo "Installing requirements..."
pip install -r requirements.txt
```

## Command-Line Options

```
usage: detect_requirements.py [-h] [-o OUTPUT] [--no-versions] [directory]

Detect Python package requirements from source files

positional arguments:
  directory             Directory to scan (default: current directory)

optional arguments:
  -h, --help            show this help message and exit
  -o OUTPUT, --output OUTPUT
                        Output file path (default: requirements.txt in scanned directory)
  --no-versions         Do not include version numbers
```

## Limitations

- Requires Python files to be syntactically correct
- Dynamic imports (e.g., `__import__()`) are not detected
- Conditional imports may be included even if not always used
- Custom package mappings may need to be added for uncommon packages

## Troubleshooting

### "Syntax error in file.py"
- Fix syntax errors in the Python file before running the detector

### "Version unknown"
- The package is imported but not installed in your current environment
- Install it first or use `--no-versions` flag

### Package not detected
- Ensure the import statement uses standard Python syntax
- Check if the package is in the excluded directories

### Wrong package name
- Add a custom mapping in `IMPORT_TO_PACKAGE` dictionary in the script
